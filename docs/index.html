Fundamentos: DevOps, DevSecOps e métricas DORA

DevOps (Development + Operations) é uma cultura organizacional apoiada por práticas técnicas e automação: integra desenvolvimento e operações com responsabilidade compartilhada, integração e entrega contínuas (CI/CD, Continuous Integration / Continuous Delivery) e ciclos rápidos de retroalimentação. Não é ferramenta, cargo nem produto.

CALMS: Cultura (sem cultura da culpa) · Automação (testes, IaC, CI/CD) · Lean (pequenos lotes) · Medição · Sharing (compartilhamento)

DevSecOps integra segurança (Security) a todas as fases. Shift Left: deslocar as verificações para o início, porque quanto mais tarde uma falha é encontrada, mais cara é a correção. DevSecOps não substitui o DevOps: é uma evolução dele.

Estudo de caso: HealthTrack Solutions Hipotético

Startup brasileira de saúde (healthtech): 25 colaboradores, 12 engenheiros. Plataforma de agendamento, prontuários e prescrições, hoje um monolito Node.js/Express em um único EC2.

ProblemaEtapa que resolve
Deploys manuais, quinzenais, de madrugada, com 3–4 engenheirosCI · CD
4 incidentes em 6 meses; recuperação média de 3 horasCD · MON
Credenciais no código; políticas IAM com *SEC (todas)
Lentidão no pico; escala manual do EC2CD (Fargate)
Diagnóstico via SSH e logs locaisMON · FEEDBACK
Conformidade com a LGPD (Lei Geral de Proteção de Dados)SEC (todas)
Etapa 1 · DEV

Desenvolvimento: código, containers e IaC

Conceito e AWS Documentado

  • Git + GitHub: branches, Pull Request (PR) e branch protection; integração com a AWS via AWS CodeConnections.
  • Containers (Docker): o mesmo artefato roda no notebook, no CI e em produção; imagem mínima node:20-alpine e build multi-stage.
  • Infraestrutura como Código (IaC) com AWS CDK: versionada, revisável em PR e testável com Jest.

Na HealthTrack Hipotético

O monolito vira 5 microsserviços Node.js/Express, cada um com imagem Docker e pipeline próprios: auth, patient, scheduling, prescription, notification. Decisões: ECS com Fargate (equipe pequena, sem Kubernetes) e CDK em TypeScript (mesma linguagem da equipe).

Neste repositório Implementado

  • api/Dockerfile: multi-stage, node:20-alpine, usuário não-root, HEALTHCHECK, só dependências de produção.
  • infra/: stack CDK do scheduling-service (VPC, ECS Fargate, ALB interno, Secrets Manager, logs e alarmes).

Segredos: credenciais no AWS Secrets Manager, com rotação automática; o buildspec.yml os lê por env.secrets-manager, nunca do código.
Menor privilégio: cada task ECS tem sua própria Task Role; ARNs específicos em vez de *; IAM Access Analyzer.
LGPD Hipotético: dados de pacientes criptografados (KMS e TLS), acesso só pelo patient-service e pelo prescription-service, trilha de auditoria no CloudTrail, exportação e exclusão de dados.

    Aprendizados (estudo, seção 8) Documentado

    • DevOps é cultural: velocidade e estabilidade não são conflitantes.
    • DevSecOps é essencial com dados de saúde: Shift Left transforma a segurança em acelerador.
    • A AWS exige planejamento: escolher os serviços certos e gerenciá-los via IaC.
    • Observabilidade é tão importante quanto a funcionalidade.
    • A jornada é gradual: CI/CD → scans → monitoramento → maturidade.
